# SWPUCAT 智能助手完整实施计划

> 文档状态：执行中

> 目标分支：`feature/agent`  
> 执行原则：每个阶段独立实现、独立验证、更新本文档后独立提交到本地 Git；未通过验收不得进入下一阶段。

## 1. 背景与目标

当前智能助手已经具备 13 个业务工具、知识库混合检索基础、会话历史、知识来源展示，以及个人工时、打卡历史、工时要求和月报周期查询能力。代码库中还存在一组尚未提交的角色化评测代码；当前运行环境只执行到数据库迁移 034，尚未部署 Agent 审计迁移和最近的 Agent 代码。

本计划的目标是把此前分析中所有未完成或部分完成的事项收口，使智能助手达到可供团队稳定使用、可观测、可评测、可治理、可回滚的状态。同时处理此前报告中的成员工时统计条形图显示异常。

## 2. 状态标记

- `[ ]`：尚未开始。
- `[~]`：正在实施，尚未满足全部验收标准。
- `[x]`：代码、测试、文档和本地 Git 提交均已完成。
- `[!]`：存在外部阻塞，必须在备注中写明原因、已完成部分和解除条件。

只有完成本阶段的代码提交后，才允许把阶段状态标记为 `[x]`。阶段实施过程中先标记为 `[~]`，最终提交必须包含本文档的状态更新和验收记录。

## 3. 完成定义

所有任务完成必须同时满足：

1. 本文档中的 P00—P10 全部标记为 `[x]`；不存在未解释的 `[ ]`、`[~]` 或 `[!]`。
2. 每个阶段至少有一个职责单一、可回滚的本地 Git 提交。
3. Go 全量测试通过：`go test -buildvcs=false ./...`。
4. 前端类型检查和生产构建通过：`npm run build`。
5. 角色化离线评测 54/54 通过，真实模型评测达到本文定义的门槛。
6. 本地 Docker 环境完成最新迁移并通过健康检查。
7. 核心流程完成端到端验收：个人工时、团队统计、知识检索与推荐、月报、写操作确认、会话删除与反馈、审计查询。
8. 不在日志、审计、接口或前端中泄露密钥、完整提示词、月报正文或不必要的个人数据。

### [ ] P03：完成 Agent 审计、费用统计和管理端可观测性

计划提交：`feat(agent): add audit analytics and cost estimation`

### [ ] P04：提升并发能力并统一超时预算

范围：

- 将生产默认并发从 1 调整为适合当前部署资源的保守值，并保留环境变量覆盖。
- 将固定 2 秒工作槽等待改为显式配置。
- 统一浏览器、主站、Agent、模型和业务工具的超时层级，确保外层预算大于内层预算并保留收尾时间。
- 为繁忙、排队超时、模型超时和客户端取消提供稳定错误码。
- 增加并发、取消和超时测试。

验收标准：

- 至少 4 个并发只读请求不会因全局槽位为 1 而立即失败。
- 达到容量上限时返回稳定、可重试的错误，不泄露内部信息。
- 客户端取消后释放资源，不继续占用工作槽。

计划提交：`feat(agent): tune concurrency and timeout budgets`

### [ ] P05：将资料推荐接入混合检索

范围：

- 让 `recommend_knowledge` 复用知识索引的关键词与向量混合检索能力。
- 保留只返回已审核、当前可见资料的约束。
- 返回匹配模式、依据、摘要和稳定来源标识。
- 无向量或嵌入服务不可用时安全降级到关键词检索。
- 避免推荐接口与搜索接口产生不一致的权限过滤。

验收标准：

- 语义相关但标题不含关键词的资料能够被推荐。
- 被隔离、待审核、已删除资料不会被推荐。
- 降级路径、无结果路径和引用收集均有测试。

计划提交：`feat(knowledge): use hybrid retrieval for recommendations`

### [ ] P06：完善会话生命周期、删除和保留策略

范围：

- 增加按所有者校验的会话删除 API 和前端确认交互。
- 删除会话时处理消息、审计关联和不可恢复提示；审计数据按合规需要保留匿名关联或解除业务关联。
- 增加可配置会话保留期限和定时清理命令，默认不自动开启破坏性清理。
- 文档化会话数据范围、保留期限、用户删除行为和管理员审计边界。

验收标准：

- 用户只能删除自己的会话。
- 删除后无法继续读取或向该会话发送消息。
- 清理任务支持 dry-run，正式执行需要显式开关。
- 删除、并发删除、重复删除和审计关联均有测试。

计划提交：`feat(agent): add conversation deletion and retention controls`

### [ ] P07：增加流式输出、停止、重试、重新生成、复制和反馈

范围：

- 增加流式聊天协议，并保持现有非流式接口兼容。
- 前端逐步显示回答，可停止当前生成。
- 失败消息支持重试；最后一轮回答支持重新生成。
- 回答支持复制和有用/无用反馈，反馈绑定会话、消息和运行审计。
- 处理断线、重复提交、取消、刷新页面和部分输出，不生成重复持久化消息。

验收标准：

- 首段内容可在完整回答结束前显示。
- 停止后服务端收到取消信号并释放资源。
- 重试和重新生成具有幂等保护，历史顺序正确。
- 复制和反馈具有明确成功/失败提示。

计划提交：`feat(agent): add streaming controls and response feedback`

### [ ] P08：为高影响写操作增加确认协议和结果卡片

范围：

- 定义 Agent 写操作的“提议—确认—执行—结果”协议。
- 打卡、签退和公告草稿等写工具在执行前返回结构化确认信息；用户明确确认后才执行。
- 确认令牌绑定用户、会话、工具、参数摘要和有效期，防止重放与串会话执行。
- 前端展示确认卡片和结构化成功/失败结果卡片。
- 保留全局写开关和服务端权限校验，不能只依赖前端。

验收标准：

- 普通自然语言中的模糊意图不会直接触发写入。
- 过期、篡改、跨用户或重复确认令牌均被拒绝。
- 工具失败时不会向用户声称操作成功。

计划提交：`feat(agent): require confirmations for write tools`

### [ ] P09：补齐高价值业务工具与安全边界

范围：

- 知识审核：仅队长/超级管理员查看待审核项并执行批准或拒绝，必须走 P08 确认协议。
- 邀请码：仅授权角色生成，返回结果采用安全卡片，不写入模型自由文本上下文。
- 考评草稿：只创建或更新草稿，不允许 Agent 直接审核或发布。
- 在线状态：提供最小化、按权限过滤的在线成员摘要，不暴露令牌、IP 或完整活动轨迹。
- 更新系统提示、工具预算、安全投影、审计契约和角色化评测用例。

验收标准：

- 每个工具均具备服务端 RBAC，越权测试覆盖普通成员。
- 高影响操作不能绕过确认流程。
- 不增加执行任意 SQL、任意 HTTP 或任意文件访问能力。

计划提交：`feat(agent): add governed team management tools`

### [ ] P10：隐私收口、真实评测、部署和最终验收

范围：

- 增加模型数据边界、第三方处理、日志脱敏、保留期限和删除行为文档。
- 检查发送给模型的上下文最小化策略，确保不发送无关成员数据。
- 执行完整 Go 测试、前端构建、离线评测和真实模型评测。
- 真实评测使用进程内业务夹具，不连接真实业务数据库；重复运行以降低偶然性。
- 构建并更新本地 Docker 服务，执行全部迁移，核对健康状态。
- 对核心用户问题进行端到端验收，并记录最终结果。

真实模型评测门槛：

- 总体通过率不低于 90%。
- 权限、隐私、提示注入和写操作安全用例必须 100% 通过。
- 同一用例重复 3 次时，安全用例不得出现一次失败。
- 未达到门槛时必须修复提示、工具或评分契约并重新评测，不能只修改期望答案掩盖问题。

验收标准：

- 数据库迁移版本达到最新，Agent 审计表存在并可写入。
- Agent、主站、数据库和前端容器健康。
- 本文档所有阶段标记为 `[x]`，最终工作区干净。

计划提交：`docs(agent): complete deployment and acceptance record`

## 6. 提交与回滚规范

- 每个阶段使用独立提交，提交信息使用 Conventional Commits。
- 不重写或删除用户已有提交，不使用 `git reset --hard`。
- 数据库迁移只能新增，已经执行的迁移不得原地改写。
- 破坏性数据操作必须提供 dry-run、显式开关或可恢复路径。
- 阶段回滚以 `git revert <commit>` 为主；数据库使用对应的新补偿迁移，不手工删除已执行迁移记录。
