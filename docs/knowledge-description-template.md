# 知识库描述字段规范模板

> 适用场景：在「知识库」页添加链接或上传文件时，填写「描述」字段。
> 目的：让每个条目的描述遵循统一结构，提升关键词命中率，并让向量化（embedding）生成更准确的语义向量，从而提高检索准确率。

## 标准模板

填充后约 300–600 字。注意：系统会自动在前面拼上「# 标题 / 分类： / 链接：」，因此模板里**不要重复标题**，直接写正文信息。

```markdown
> 用途：一句话说明什么情况下使用这份资料
> 关键词：关键词一、关键词二、关键词三
> 适用对象：成员 / 队长 / 全体

## 内容摘要
用 2~3 句话概括这份资料回答什么问题、包含哪些核心内容。

## 使用要点
- 要点一：……
- 要点二：……

## 注意事项
- 说明限制、假设或边界（例如「以系统实时查询为准」）。
```

## 填写示例

```markdown
> 用途：查询上班打卡、下班签退的规则与异常处理
> 关键词：打卡、签退、工时、异常、补签
> 适用对象：全体成员

## 内容摘要
介绍打卡与签退的正常流程：同一天按时间顺序配对的上班—下班记录才会计入工时；日终会对未签退记录按 23:59:59 自动签退。

## 使用要点
- 开工执行上班打卡，收工执行下班打卡。
- 仍处于上班状态的记录，日终任务会按 23:59:59 自动签退。

## 注意事项
- 异常记录助手不会自行猜测或补齐，需队长/超级管理员核对补签。
- 具体工时要求请以系统实时查询为准。
```

## 各部分说明

| 字段 | 作用 |
|---|---|
| 用途 | 一句话说明「什么时候该用它」，帮助查询意图定位 |
| 关键词 | 提升 `word_similarity` / `ILIKE` 的命中率（用户可能搜索的词） |
| 适用对象 | 说明受众范围，辅助过滤和理解 |
| 内容摘要 | 2~3 句概括核心内容，是向量语义的主体 |
| 使用要点 | 结构化要点，便于逐条匹配 |
| 注意事项 | 边界/限制，覆盖「以系统实时查询为准」类约束，避免模型臆测 |

## 为什么 / 如何生效

- 描述在 `internal/application/knowledgeindex/service.go` 里会被 `sourceDescription` 组装进检索文本，再分块、可选嵌入。
- 关键词检索在 `knowledge_index_repo.go` 直接对 `name / description / chunk.content` 打分，因此模板里的「用途 / 关键词」等词即命中词。
- 当前部署为 `hybrid` 检索（关键词 + 向量融合），结构化描述会生成语义更聚焦的向量。

## 软提示

- 当描述去除首尾空白后**少于 20 个字符**时，创建/上传接口会返回一个**非阻断**的 `warnings` 提示，不阻止提交：
  - 后端阈值：`internal/interfaces/http/knowledge_handler.go` 的 `descriptionWarnings`（`descriptionMinRunes = 20`）。
- 前端在成功后展示该提示，引导补充模板内容。
