# 智能助手模型数据边界与隐私运维规范

## 适用范围

本文说明 SWPUCAT 智能助手在调用 OpenAI-compatible 模型时，哪些数据可能离开主站进程、哪些数据必须留在本地，以及日志、保留和删除的责任边界。它适用于普通对话、知识检索、月报总结、团队查询和所有待确认写操作。

模型服务商是独立的数据处理边界。项目只能控制发出的请求和本地存储，不能代替服务商承诺训练用途、地域、加密、人员访问或服务端保留期限。部署方必须根据实际供应商的合同、数据处理协议和控制台设置完成评估；无法确认时，不应向该模型发送真实成员数据。

## 发送给模型的数据

每次推理只发送完成当前请求所需的受限上下文：

- 固定系统指令和当前已注册工具的名称、说明、参数结构；
- 当前用户消息，最多 4000 个 Unicode 字符；
- 最多 40 条、总输入不超过 64000 字符的会话历史，以及最多 8000 字符的滚动摘要；进入模型前动态上下文再次压缩到最多 16000 字符，优先保留当前问题和最新资料；
- 主站按当前登录用户权限返回的工具结果；普通成员只能获得本人数据，团队统计、待审知识和团队月报仅向授权角色开放；
- 最多 8 条知识来源的受限投影。知识上下文最多 9000 字符和 16 KiB，字段会截断，超限时先缩短说明和片段，再丢弃低优先级来源；
- 模型自己生成的工具调用参数及工具返回的最小业务投影。

授权角色请求团队总结时，成员显示名、工时汇总和月报正文可能进入模型上下文。队长或超级管理员查看待审知识时，条目名称、说明、上传人显示名和创建时间可能进入模型上下文。在线状态工具对普通成员仅返回总人数、在线人数和本人状态；队长或超级管理员最多看到 50 个在线成员显示名。

知识资料、历史消息、滚动摘要和工具结果都按不可信数据处理，不能覆盖系统指令、角色或权限。工具仍通过主站 API 和服务端 RBAC 获取数据，模型不能执行任意 SQL、任意 HTTP 请求或任意文件访问。

## 不发送给模型的数据

以下数据不得进入模型消息、工具自由文本结果或模型可见错误：

- JWT、刷新令牌、Cookie、内部共享密钥、模型 API Key、数据库密码和对象存储凭据；
- 确认令牌及其签名、摘要和 nonce；
- 确认后才生成的真实邀请码；
- IP、设备标识、完整活动轨迹和文件存储键；
- 审计表原始记录、数据库连接信息和未授权用户的会话；
- 工具或模型供应商的原始错误响应正文。

业务客户端在服务端使用当前请求的授权头调用主站，但授权头存放在 Go `context` 中，不属于模型参数或工具 JSON。所有写工具在模型阶段只产生“待确认”提议；真实知识审核、邀请码生成、考评草稿保存、打卡和公告草稿创建均在用户点击确认后由主站执行，结果卡片不会再次送回模型。

## 本地持久化与日志

会话数据库保存用户问题、助手回答、滚动摘要、来源和结构化卡片，以支持历史恢复。确认卡片落库前会移除原始确认令牌；确认记录只保存令牌摘要、参数摘要、状态和确定性结果。

Agent 运行审计不保存提示词、回答正文、授权头或原始工具参数。模型审计只保存供应商/模型标识、状态、耗时和 Token 数；工具审计使用白名单投影，例如参数是否提供、枚举、字符数、结果数量和状态分布。未知工具按写操作保守分类，无法满足投影契约的载荷记为无效，不原样落库。

生产环境不得启用请求体日志、反向代理 body dump、数据库 SQL 参数日志或模型 SDK 的原始请求调试输出。异常日志只记录稳定错误码和必要的关联 ID；排障材料不得复制真实提示词、模型响应、令牌或邀请码。

## 保留、删除与服务商责任

本地会话删除和自动清理遵循 [智能助手会话删除与保留策略](agent-conversation-retention.md)。用户删除会话会永久删除本地正文和消息，并解除审计的会话关联；合规审计的最小元数据可继续保留。

本地删除不会自动删除模型服务商此前处理或保留的数据。部署方必须：

1. 选择明确支持所需数据地域、保留期限和“不用于训练”条款的供应商或自托管模型；
2. 将供应商侧保留期限设置为组织允许的最短值，并记录生效范围；
3. 建立供应商侧访问、导出和删除请求流程，把供应商工单或 API 操作纳入用户删除响应；
4. 更换供应商、模型或 Base URL 时重新完成隐私和安全评审。

## 上线检查清单

- 确认 `CSA_LLM_BASE_URL` 指向已批准的服务商，API Key 只注入 Agent 容器，不注入浏览器或主站响应；
- 确认 Agent 服务不暴露宿主机端口，只允许主站通过内部网络调用；
- 确认 `CSA_AGENT_INTERNAL_SECRET`、JWT 密钥和数据库密码使用独立高强度值；
- 使用普通成员、队长和超级管理员账号分别验证个人、团队和待审数据边界；
- 运行 54 条角色化评测，并要求权限、隐私、提示注入和确认安全场景零失败；
- 检查 Agent 审计样本，确认不存在正文、令牌、邀请码、成员姓名或文件存储键；
- 核对供应商合同、训练用途、保留期限、地域、删除流程和事件通知联系人；
- 在隐私声明中向用户说明模型供应商类别、处理目的、可能发送的数据类型及删除限制。

## 事件响应

发现疑似泄露时，应立即禁用 `CSA_AGENT_ENABLED` 或撤销 Agent 服务流量，轮换模型 API Key、内部共享密钥和受影响凭据，保留不含正文的关联 ID、时间和审计元数据，并检查供应商控制台。若确认数据已发送到错误端点，应按组织流程通知安全与隐私负责人，向供应商提交删除请求，并在恢复前补充回归用例。
